# 整改记录 43：双倍额度扩展 0.1.1 集成与真实加载目录识别

日期：2026-07-12

## 根因

此前上游嵌入包的 Chrome `manifest.json` 仍标记为 `0.1.0`，即使 CodexBridge 覆盖了固定目录，Chrome 扩展详情仍会显示旧版本。此外，宿主只识别 Chrome Preferences 中 `location=4` 的扩展记录；不同 Chrome 构建使用其他 location 数值时，实际加载目录会被漏掉，导致只更新固定目录而没有覆盖 Chrome 正在加载的目录。

## 修改

- 审计并替换为 Embedded ZIP `20260712-134707`，SHA-256 为 `F9977A8262ACA0385ADEDE9AEF5802B19845CE86235A911B7C72472E89133D2F`。
- 内置扩展清单版本更新为 `0.1.1`，用户可见版本为 `0.1.1 - 20260712`。
- Chrome 加载目录不再依赖不稳定的数字 location 枚举；改用绝对路径并严格验证 Bridge manifest、service worker 与内容脚本。
- 状态接口返回扩展清单版本和用户可见版本，双倍额度页面直接展示该版本。
- 保留固定用户目录部署，并在识别到实际加载目录时同步覆盖该目录且逐文件校验。

## 验证

- 新 ZIP：42 个文件，SHA-256、清单版本和协议标识均匹配上游说明。
- 新增不同 Chrome location 枚举的回归用例，修复前失败、修复后通过。
- 测试机验收以 Chrome 扩展详情显示 `0.1.1 - 20260712`，且诊断接口满足版本一致、已连接、无需重载为准。
