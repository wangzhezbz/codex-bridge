# 整改记录 33：非 GPT 模型中文自然生图请求未进入已配置图片代理

## 现象

DeepSeek、Kimi、豆包等非 GPT 模型已经绑定图片供应商，但用户输入“帮我生成一张机械恐龙”后，请求仍按普通聊天发送给文本模型。文本模型看不到可调用的托管 `image_generation` 工具，因而错误提示需要 `OPENAI_API_KEY` 或改用 CLI。

## 根因

非 GPT 路由的图片代理入口依赖明确的生图意图识别。原识别器能处理“生成一张图片”“生成一个图标”等带图片类别词的表达，却没有识别“生成一张/一只具体对象”这种中文自然说法。配置没有丢失，失败发生在请求进入图片供应商之前。

## 修改

- 已配置 `mode=custom` 图片代理的 Chat Completions 路由，现在识别“生成/画/绘制/制作 + 张/幅/只/位/条/组 + 具体对象”。
- 不要求客户端额外指定 `tool_choice=image_generation`；自然语言明确要求生图即可进入已绑定图片供应商。
- 保留非视觉排除：报告、文档、代码、组件、网页、清单、计划、视频、动画等不会被误当图片请求。
- GPT 原生 `image_gen` 路径没有改动。

## 验证

- RED：现场语句“帮我生成一张机械恐龙”在已配置 DeepSeek 图片代理上返回 `false`。
- GREEN：同一语句返回 `true`。
- Router 集成测试：不传 `tool_choice`，请求直接到配置的 `/images/generations`，使用配置的图片模型并返回图片结果。
- 相关图片代理、GPT 原生生图、交互式 Computer Use 防误拦截、智能路由测试 10/10 通过。

## 边界

本轮没有修改会话恢复、provider 历史作用域或资源统计逻辑。
