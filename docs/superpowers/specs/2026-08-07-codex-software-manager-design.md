# CodexBridge 软件管理设计

日期：2026-08-07

状态：设计已逐项确认，等待用户复核后编写实施计划

## 1. 目标

在 CodexBridge Windows 桌面端内新增“软件管理”，统一完成以下四类操作：

1. 下载安装 ChatGPT、V2RayN、Git 和用户选择的 Skills。
2. 检查并安装 ChatGPT、V2RayN 和 Git 的新版本。
3. 精确卸载指定程序或指定 Skill，同时保护用户数据。
4. 对最近一次成功更新且具备上一版本的组件执行一次性回滚。

这不是对旧安装器的简单套壳。客户端安装、更新、卸载、回滚、下载、校验、解压、状态和日志全部由 CodexBridge Electron 主进程重新实现。旧项目代码只用于参考已经验证过的长路径、断点续传、进程处理、快捷方式和数据保护规则；CodexBridge 不下载或执行旧的 `codex.ps1`、`update-codex.ps1`、`clean-codex.ps1`。

## 2. 硬性边界

- 只新增独立的 CodexBridge 服务端环境，不修改原 `/install/`、`/install-test/`、对应服务器目录、清单、密钥、定时任务或对象存储前缀。
- 当前阶段只建设新的测试/验收环境。没有用户明确授权，不创建或发布新的正式环境。
- Windows 才能使用软件管理；macOS 不展示入口，也不能调用 Windows 安装能力。
- 所有文件、下载、进程、快捷方式和安装操作都在 Electron Main Process 中执行。
- Renderer 只能发送固定动作、固定组件 ID、固定 Skill ID 和通过系统目录选择器得到的安装根目录；不能传脚本、命令、下载 URL 或任意删除路径。
- 同一时间只能执行一个安装器任务。
- 不使用用户当前电脑做真实安装、更新、回滚或卸载验收。
- 不把自动化测试、模拟包测试或静态检查描述为真实安装成功。

## 3. 页面结构

左侧导航只新增一个“软件管理”入口。页面内部使用标签切换：

- 下载安装
- 检查更新
- 卸载软件
- 回滚

没有有效回滚记录时只显示前三个标签。成功更新至少一个支持回滚的组件后才显示“回滚”。

### 3.1 下载安装

- 默认勾选 ChatGPT。
- V2RayN、Git 和所有 Skills 默认不勾选。
- 显示 ChatGPT 当前服务器版本。
- V2RayN 旁展示注册链接：`https://w1.soxo.top/auth/register?code=2aEq`，由系统浏览器打开。
- 用户选择一个安装根目录，默认 `%LOCALAPPDATA%\CBApps`；记住上次安全选择。
- 页面显示已选数量、预计下载大小和执行顺序。
- 多个组件按顺序逐个下载和安装。
- 组件之间相互独立，允许部分成功；某一组件失败不撤销其他已经成功的组件。

### 3.2 检查更新

- 有新版的已安装组件默认勾选。
- 已是最新版的组件不可勾选，显示“已是最新版”。
- 未安装组件默认不勾选；用户勾选后按首次安装处理。
- ChatGPT 和 V2RayN 的外部安装完全忽略，只判断 CodexBridge 自己管理的安装。
- Git 若已存在则更新原安装；没有 Git 才安装到用户选择的根目录。
- 所有选择按顺序逐个处理。

### 3.3 卸载软件

- 所有程序和 Skills 默认不勾选。
- 不存在的选择安全跳过，不伪造失败。
- 不展示“同时删除组件数据”之类的选项。
- 卸载只删除程序本体、CodexBridge 创建的启动器、CodexBridge 记录的快捷方式和用户明确选择的 Skills。
- 永远保留 ChatGPT/Codex 的 `%USERPROFILE%\.codex` 登录、配置、项目和历史。
- 永远保留 V2RayN 的订阅、节点和用户配置。
- 永远保留 Git 的 `.gitconfig`、SSH 密钥、凭据和项目仓库。

### 3.4 回滚

- 只展示最近一次成功更新且本机仍保存上一版本的组件。
- 第一次安装不产生回滚记录。
- Skills 不支持回滚。
- 用户原有 Git 只负责更新，不支持回滚。
- CodexBridge 安装的 Git、ChatGPT 和 V2RayN 可支持回滚。
- 回滚使用本机上一版本，不重新下载。
- 回滚成功后删除有问题的新版并清除该组件的回滚记录；需要再升级时重新走更新流程。

## 4. Skills 规则

下载和卸载共用同一个 Skills 选择器组件：

- 固定高度列表。
- 支持按名称和用途搜索。
- 支持滚动。
- 显示总数和已选数量。
- 默认全部不勾选。
- 下载页列出服务端当前可安装的 Skills。
- 卸载页只列出本机已经安装的 Skills。

Skills 不设在线自动更新流程。用户提供新的 Skill 集合后，服务端替换当前目录；用户安装时始终取得当前最新版。

若用户选择安装一个已经存在的同名 Skill，直接用服务端当前版本替换原目录，不比较内容、不备份、不恢复。卸载该 Skill 时直接删除目标目录。安装确认页必须提示：“同名 Skill 将被替换，原内容不会保留。”

同名替换和卸载只能作用于“当前 Codex 实际 Skills 根目录”的直接子目录。目标目录名必须来自已验签的固定 Skill ID，并同时满足规范化路径仍位于 Skills 根目录、不是根目录本身、不是重解析点或链接。Renderer 不能提交路径；主进程根据固定 ID 重新计算唯一目标。任一校验失败时停止该 Skill 操作，不尝试猜测或扩大删除范围。

## 5. 组件差异

| 组件 | 来源 | 外部安装处理 | 桌面快捷方式 | 回滚 |
|---|---|---|---|---|
| ChatGPT | 用户提供版本包，人工发布 | 完全忽略，安装 CodexBridge 独立版本 | `ChatGPT` | 支持 |
| V2RayN | 服务端定时检查指定页面和固定 7z 地址 | 完全忽略，安装 CodexBridge 独立版本 | `V2RayN` | 支持 |
| Git | 服务端定时检查 Git 官方 Windows 版本 | 已安装则原地更新；未安装则由 CodexBridge 安装 | 不创建 | 仅 CodexBridge 安装的 Git 支持 |
| Skills | 用户人工提供当前集合 | 同名时强制替换 | 不创建 | 不支持 |

快捷方式不得覆盖用户已有同名文件。若桌面已有 `ChatGPT` 或 `V2RayN`，依次创建 `ChatGPT（1）`、`ChatGPT（2）` 或 `V2RayN（1）`、`V2RayN（2）`。卸载时只删除安装清单记录的具体快捷方式。

Git 必须区分两种归属。CodexBridge 安装的 Git 由状态清单记录安装目录，可更新、卸载和回滚；用户原有 Git 只在 Windows 卸载注册信息与目标 `git.exe` 能唯一对应时允许原地更新或显式卸载，不复制到受管目录、不创建回滚槽位。若检测到多个 Git、便携版、来源不明或卸载信息不完整，页面显示具体冲突并禁止对外部 Git 执行修改。卸载页必须显示将操作的 Git 路径和“用户已有/本工具安装”归属，用户未勾选时不作任何处理。

## 6. 新服务端环境

建议并已确认的独立环境：

- 服务器根目录：`/opt/shanhai/codexbridge-installer/`
- 测试地址：`https://shanhaiyouling.com/codexbridge-install-test/`
- 对象存储测试前缀：`/codexbridge-test/packages/`
- 未来正式地址：`https://shanhaiyouling.com/codexbridge-install/`，当前不创建、不调用

新环境使用独立 RSA 签名密钥。私钥只保存在服务器或 CI Secret 中；CodexBridge 只内置公钥。

公开文件包括：

- `component-catalog.json`
- `component-catalog.json.sig`
- 版本化 ChatGPT、V2RayN、Git 安装包
- Skills 当前目录及其文件清单

组件清单至少记录：

- 稳定组件 ID 和显示名称
- 版本
- Windows 架构
- 包格式
- 下载地址
- 文件大小
- SHA256
- 程序入口
- 必要文件列表
- 包内最大相对路径长度
- 发布时间
- 是否支持回滚

发布顺序固定为：上传版本化安装包，验证远端大小和哈希，上传签名，最后原子替换 JSON 清单。版本化对象不得覆盖。

### 6.1 上游同步

- ChatGPT：用户每次提供新包，发布流程验证版本、大小、SHA256 和入口文件后上传。
- V2RayN：定时任务检查 `https://v1.v2ai.top/doc/#/Windows/V2free` 和 `https://v1.v2ai.top/ssr-download/v2rayn.7z`。固定 URL 不能作为版本依据；必须下载到临时目录并检查大小、哈希和包内程序版本，确认变化后上传版本化对象。
- Git：定时任务从 `https://git-scm.com/downloads/win` 对应的官方 Windows 发布来源检查新版。
- Skills：不设自动更新；用户提供新的当前集合后人工发布。

服务端每个程序组件只长期保留当前发布包和一个回退包；临时下载和更老包在新版本发布验证完成后删除，避免存储持续增长。

## 7. 客户端目录

默认根目录为 `%LOCALAPPDATA%\CBApps`。用户可以修改，但必须拒绝：

- Windows、Program Files 等系统目录
- 磁盘根目录
- `.codex`、桌面、文档等用户数据目录
- UNC/网络目录
- 不可写目录
- 根据清单最大相对路径计算后不安全的过长目录

只有 ChatGPT 使用短槽位，避免深层 Electron/Node 文件超过 Windows 路径限制：

```text
CBApps\
  c\      ChatGPT 当前版本
  cp\     ChatGPT 上一版本
  ct\     ChatGPT 更新临时目录
```

其他组件保留可读目录名称，例如：

```text
CBApps\
  V2RayN\
    当前版本\
    上一版本\
  Git\
    当前版本\
    上一版本\
  downloads\
  staging\
  state\
  logs\
```

ChatGPT 仍使用官方 `%USERPROFILE%\.codex`。V2RayN 的持久配置与程序版本目录分离。Skills 安装到当前 Codex 实际识别的 Skills 目录，归属记录保存在状态清单中。

## 8. 客户端模块

- `CodexManagerService`：单任务调度和对外状态。
- `ComponentCatalog`：下载并验证签名组件清单。
- `DownloadManager`：HTTP Range、`.part`、速度、进度、重试和空间检查。
- `PackageVerifier`：大小、SHA256、类型、必要文件和路径上限。
- `ArchiveService`：ZIP/7z 枚举、安全校验、长路径解压和临时目录管理。
- `ChatGptInstaller`、`V2RayNInstaller`、`GitInstaller`、`SkillInstaller`：组件特定规则。
- `VersionSlotManager`：当前版本、上一版本、临时版本和最老版本清理。
- `OwnershipManifest`：组件、Skills、快捷方式、版本、哈希和路径归属。
- `RollbackManager`：一次性回滚。
- `TransactionJournal`：断电或崩溃后的恢复依据。
- 固定 IPC 和 Renderer 页面：只传受控动作及 ID。

归档和安装格式采用白名单：ChatGPT 与 Skills 使用发布流程规范化后的 ZIP 包，V2RayN 使用已验签清单声明的 7z 包，Git 使用来自官方发布源且通过 Authenticode、大小和 SHA256 校验的 Windows 安装程序。主进程负责全流程编排；ZIP 使用应用内库处理，7z 使用随应用固定版本分发并校验哈希的解压组件，Git 仅以固定参数启动已验证的官方安装程序。任何格式、入口或签名不符合清单时直接拒绝，不回退执行包内脚本或远程命令。

## 9. 下载、安装和验证

各组件按顺序执行以下公共阶段：

1. 获取并验证签名清单。
2. 检查目标路径、磁盘空间和当前任务锁。
3. 下载到 `.part`，支持 Range 续传和有限重试。
4. 校验长度、SHA256 和包格式。
5. 枚举压缩包并拒绝绝对路径、盘符路径、`..`、链接逃逸和其他路径穿越。
6. 解压到受控临时目录。
7. 验证必要文件、入口和版本。
8. 执行组件安装或版本切换。
9. 写入状态清单和快捷方式记录。
10. 清理成功任务的安装包和临时目录。

安装或更新成功不能只依据进程退出码。最低验证标准：

- ChatGPT：受管目录中的 `ChatGPT.exe` 存在，PE/包内版本与签名清单一致，状态清单版本和包 SHA256 一致，快捷方式目标正确。
- V2RayN：入口及必要核心文件存在，程序版本与清单一致，原持久配置仍可读取，快捷方式目标正确。
- Git：执行目标安装目录内的 `git.exe --version`，退出码为零且版本匹配；不能误用 PATH 中另一份 Git。
- Skills：`SKILL.md` 和清单声明的文件存在，安装后哈希匹配。

更新前正在运行的 ChatGPT 或 V2RayN 才在更新后重新启动，并验证启动进程路径属于 CodexBridge 管理目录且未立即异常退出。更新前未运行时不强制打开窗口。V2RayN 节点能否联网和 ChatGPT 是否登录不属于安装成功判断。

## 10. 两代版本和回滚

- 首次安装只产生当前版本。
- 更新前，新包必须已经下载、校验和解压完成。
- 更新成功后保留新当前版本和更新前版本。
- 再次更新时，旧的上一版本只有在新版本完整切换成功后才删除；正常状态最多两个版本。
- 更新过程中允许短暂存在三个版本，磁盘空间检查必须按峰值计算。
- 回滚成功后删除问题新版，上一版本成为当前版本，并删除回滚记录。
- 回滚失败时不删除任何仍完整的版本，并按事务日志恢复到最后一致状态。

## 11. 取消、失败和恢复

- 检查、下载、校验、解压阶段允许取消。
- 下载取消保留一个 `.part` 文件。
- 解压取消只清理本次受控临时目录。
- 进入版本切换、Git 安装或程序删除阶段后，取消按钮显示“正在完成关键操作”并禁用。
- 每次正式文件切换前写入事务日志；CodexBridge 下次启动时检查未完成事务并恢复到最后完整版本。
- 一个组件失败不撤销其他成功组件。
- 失败结果包括组件、阶段、错误摘要、重试动作和可复制完整报告。
- UI 最多显示最近 500 行日志；完整日志写入安装根目录。
- 日志必须隐藏 Token、注册码、代理订阅、凭据和其他敏感信息。
- 关闭窗口时任务继续在托盘运行；真正退出程序时提示任务仍在进行。

## 12. 安全要求

- 不执行远程 PowerShell 或远程脚本。
- 清单必须通过独立公钥的 RSA 签名验证。
- 包必须同时通过大小、SHA256 和必要文件验证。
- 所有删除目标先规范化，并验证属于状态清单记录的受控路径。
- 不根据 Renderer 文本、文件名猜测或递归删除用户目录。
- 解压时逐项检查目标仍位于临时根目录内。
- 长路径能力用于正确处理受控文件，不用于放宽最终安装路径验证。
- 外部 ChatGPT 和 V2RayN 的进程、目录、快捷方式及注册表不属于受管范围。
- Git 原地更新只针对明确识别出的 Git 安装信息，不能扫描并修改其他开发工具。

## 13. 测试和验收

### 13.1 当前电脑允许的测试

当前电脑只运行源码测试、静态检查、模拟清单、模拟包和项目临时目录中的集成测试。禁止：

- 安装、更新、卸载或启动真实 ChatGPT、V2RayN、Git。
- 停止当前 ChatGPT/Codex 进程。
- 修改注册表、PATH、桌面快捷方式、`.codex` 或 V2RayN 配置。

### 13.2 自动化覆盖

自动化测试覆盖签名与环境隔离、受限 IPC、续传与重试、损坏包、路径穿越、长路径、单任务锁、各阶段取消、事务恢复、外部安装隔离、Git 差异、两代版本、一次性回滚、Skills 强制替换、统一 Skills 选择器、快捷方式重名、macOS 隔离，以及现有 Router、模型、MCP、流式输出和桌面功能回归。

GitHub Actions 临时 Windows 机器负责模拟包和可自动化的安装事务测试。

### 13.3 真实验收

真实安装、更新、回滚和卸载只能在独立、可销毁的 Windows 测试机上进行。验收包括：

1. 从新环境安装四类组件。
2. 验证自定义目录、版本、快捷方式和 Skills。
3. 发布测试新版并逐组件更新。
4. 验证最多保留两代版本。
5. 执行 ChatGPT、V2RayN 和受管 Git 回滚。
6. 分别卸载程序和单个 Skill。
7. 验证 `.codex`、V2RayN 配置、Git 配置、SSH 密钥和项目文件未删除。
8. 验证原生产、原测试目录和线上地址没有变化。

若没有独立 Windows 测试机，必须明确报告“真实验收尚未完成”。

## 14. 不在本阶段范围内

- 修改或迁移原安装器生产、测试环境。
- 新 CodexBridge 正式环境发布。
- macOS 软件安装管理。
- 管理用户外部安装的 ChatGPT 或 V2RayN。
- 用户原有 Git 的回滚。
- Skills 自动更新、历史版本或回滚。
- 删除用户登录、历史、订阅、SSH 密钥、凭据或项目数据。

## 15. 完成标准

只有同时满足以下条件才能进入发布讨论：

- 代码与自动化测试通过。
- 新服务端测试环境独立部署并通过签名、URL、大小和哈希验证。
- GitHub Actions 临时 Windows 测试通过。
- 独立 Windows 测试机完成真实安装、更新、回滚和卸载验收。
- 现有 CodexBridge Router、模型、MCP、历史、流式输出、图片和自定义模型回归通过。
- 原安装器生产与测试环境经只读核对确认未变化。
