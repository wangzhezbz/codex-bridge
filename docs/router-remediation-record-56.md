# 整改记录 56：自定义中转模型列表刷新兼容

## 用户现象

用户在自定义供应商中配置 OpenAI 兼容中转后，点击“更新模型列表”，请求即使成功也不会更新界面中的可选模型；修改中转地址但不重新填写已经保存的 API Key 时，刷新还可能继续请求旧地址。

## 根因

1. 自定义供应商的 `/models` 响应已经写入模型目录缓存，但模型目录构建只消费内置供应商缓存，自定义供应商仍固定显示创建时的种子模型。
2. 刷新按钮只有在当前 API Key 输入框非空时才先保存供应商设置；已保存密钥场景下，用户新改的 Base URL 没有进入本次刷新。
3. 用户若把完整的 OpenAI 兼容接口地址（例如 `/v1/chat/completions` 或 `/v1/responses`）填入 Base URL，旧逻辑会错误拼成无效的模型列表地址。

## 修复

1. 模型目录统一合并内置供应商和自定义中转的远程目录；自定义中转首次刷新后，以远程模型列表替换种子占位模型。
2. 远程目录模型保留 `custom=true` 和自定义供应商路由属性，不套用内置供应商的特殊协议推断。
3. 刷新前只要供应商编辑卡存在就保存当前设置；空密钥不会覆盖本地已保存密钥。
4. 兼容根 Base URL、`/v1/chat/completions`、`/chat/completions`、`/v1/responses`、`/responses` 及 compact 端点，并规范化到对应 `/models` 地址。
5. 远程刷新替换旧种子模型后，原选择会安全迁移到该自定义供应商返回的首个可用模型，Router 路由保持供应商、接口、Base URL 和 Key 环境变量一致。

## 失败优先证据

修复前新增回归测试分别稳定复现：

- 自定义中转刷新后仍只显示种子模型；
- 修改 Base URL 但密钥输入框为空时不保存当前表单；
- 完整接口地址被错误拼接，模型刷新失败；
- 种子模型被远程目录替换后，已有选择没有迁移到同一自定义供应商。

## 验证结果

- `tests/desktop-settings.test.js`：347/347 通过。
- `tests/desktop-renderer.test.js`：58/58 通过。
- 定向覆盖内置供应商模型刷新，确认原有内置供应商行为未回退。
- 定向覆盖自定义中转目录、完整端点、已保存密钥和 Router 路由生成。
