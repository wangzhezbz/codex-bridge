# 整改记录 53：火山方舟刷新目录混入非对话模型与名称不可读

日期：2026-07-18

## 用户反馈

- 使用内置“Volcano Ark / Doubao”供应商刷新模型后，目录出现一百多个模型。
- 向量、图片和视频模型被错误标记为 Chat，选择后会走错误的聊天接口并被上游拒绝。
- 模型卡片使用“Doubao + 原始模型 ID”作为标题，标题与下方 ID 基本重复，无法快速辨认。

## 根因

1. 火山方舟的模型目录包含文本生成、多模态、向量化、图片生成、视频生成等不同能力类型。
2. CodexBridge 过去只读取 `/models` 返回项的 `id`，丢弃显示名、任务类型和能力元数据。
3. 目录里的每个 ID 都被强制转换为 `chat_completions` 模型，因此非对话模型也进入了聊天模型栏。
4. 缺少上游显示名时，界面直接拼接供应商短名和原始 ID，造成名称重复且不可读。

## 修复

- 原始模型目录继续完整保存，便于诊断，不删除上游返回的任何 ID。
- 火山方舟聊天模型栏只接纳与当前 Chat Completions 路由兼容的模型。
- 明确排除 embedding、rerank、Seedream、Seedance、SeedEdit、语音、3D、实时等非聊天接口模型。
- 优先使用上游返回的 `display_name`、`displayName`、`title` 或独立 `name`。
- 上游没有显示名时，将方舟原始 ID 转换为可读名称，例如：
  - `doubao-seed-2-0-pro-260215` → `Doubao Seed 2.0 Pro · 2026-02-15`
  - `mistral-7b-instruct-v0.2` → `Mistral 7B Instruct v0.2`
- 请求使用的真实 `model` 字段仍保持原始 ID，不用显示名替换，避免改变上游调用契约。
- 远程目录返回的任务类型、端点类型、分类和能力元数据会被保留，后续可优先按权威元数据分类。

## 安全边界

- 只对内置火山方舟供应商的远程目录执行能力过滤和可读名称转换。
- 不改变内置豆包预设、其他供应商刷新、API Key、Base URL、模型选择策略或故障切换策略。
- 不把非对话模型删除出原始缓存；它们只是不再冒充 Chat 模型进入当前模型栏。
- 已选中的失效非对话目录项会继续由现有模型引用修复流程处理，不复制或伪造替代模型。

## 回归验证

- 新增“非对话模型不进入火山方舟聊天目录”失败用例，修复前失败、修复后通过。
- 新增“显示名可读且不改变原始模型 ID”失败用例，修复前失败、修复后通过。
- 验证刷新得到的语言模型继续使用 `chat-doubao` 适配器，并过滤火山方舟当前模型不支持的 `reasoning` 参数。
- 验证同步后的豆包语言模型仍生成：
  - `provider=volcengine`
  - `providerFamily=doubao`
  - `api=chat_completions`
  - 原始上游模型 ID 不变
