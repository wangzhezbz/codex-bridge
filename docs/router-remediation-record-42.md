# 整改记录 42：Chrome 解压扩展一次性迁移流程

日期：2026-07-12

## 结论

测试机磁盘中的固定目录已经更新，但 Chrome 仍运行从旧目录加载的解压扩展。`chrome.runtime.reload()` 只会重新读取原加载目录，不能把一个已加载的解压扩展自动改指向另一个目录。

## 修改

- 不再把服务端配置目录冒充为 Chrome 当前加载目录。
- 无法定位旧加载目录时，按钮改为“安装新版扩展”。
- 点击按钮后复制固定目录路径并打开 Chrome 扩展页。
- 页面只显示面向用户的状态和一次性操作，不显示协议号、UTC 时间、内部管理链路等开发字段。
- 完成一次固定目录迁移后，后续更新可直接覆盖同一目录并由 Chrome 重新加载。

## 验证

- 现场条件回归测试：诊断接口有 `sourceDir`、Chrome 配置没有真实加载目录时，状态必须进入重新安装而不是假装已经覆盖当前扩展。
- 渲染测试确认迁移操作会复制目录路径并打开 Chrome 扩展管理页。
