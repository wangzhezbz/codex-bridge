# 整改记录 49：手动切换模型后的旧供应商重连隔离

日期：2026-07-13

## 用户反馈

- 用户已经从 Kimi 手动切换到 GPT-5.6，且没有开启“自动选模型”，界面仍继续显示 Kimi 限流并重复重连。
- 这不是自动路由或失败自动切换，而是 Codex Desktop 在切换模型后仍发送旧模型的重连请求。

## 根因

1. Codex Desktop 会先通过 Responses 模型设置接口记录用户刚选择的模型。
2. 正在重连的旧请求仍可能携带切换前的 `model`，Router 原先没有把模型设置事件和后续重连请求按任务作用域关联。
3. 结果是旧 Kimi 请求继续命中 Kimi，即使当前界面已经显示 GPT-5.6。

## 修复

- 新增短时模型选择状态，只记录 Codex Desktop 明确发送的模型设置事件。
- 使用 thread、window、installation 和 response ID 作为隔离作用域，不跨任务共享模型选择。
- 仅当请求满足以下全部条件时修正旧模型：
  - 当前作用域刚发生明确的模型切换；
  - 请求仍携带切换前的旧模型；
  - 请求具有 `previous_response_id` 或明确的重连状态；
  - 新模型仍存在于当前已启用模型列表。
- 普通新请求、其他任务和未发生手动切换的请求保持原模型，不启用自动选模或失败切换。

## 验证

- 单元测试覆盖同任务旧请求修正、跨任务隔离、普通新请求不改写、按 response ID 恢复历史模型提示。
- Router 集成测试复现 Kimi 429 后切换 GPT-5.6，再发送携带旧 Kimi 模型的重连请求；修复后只调用 GPT 上游，不再第二次调用 Kimi。
- 与自定义 Responses 压缩续接修复一起完成项目全量测试与 Windows 打包版冒烟测试。

## 安全边界

- 未开启或扩大自动选模型、失败自动切换和备用模型逻辑。
- 未把一次模型选择扩散到其他任务、窗口或安装实例。
- 模型选择状态有短时过期限制，并只接受当前配置中仍启用的模型。
- 未删除任何文件或目录。
